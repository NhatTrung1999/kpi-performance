# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Repo layout: `frontend/` (this app — React 19 + TypeScript + Vite 8 + Tailwind v4) and `docs/design-system.md` (token tables and design rules, in Vietnamese). There is no backend in the repo; the app talks to an API at `VITE_API_URL` (default `/api`). Code comments are Vietnamese. **UI text goes through i18n** (Vietnamese by default, English kept; see below) — never hard-code user-visible text in components. Unit tests use Vitest (`*.test.ts` next to the code).

## Commands (run from `frontend/`)

- `npm run dev` — Vite dev server
- `npm run build` — `tsc -b && vite build` (type-check is part of the build)
- `npm run lint` — ESLint
- `npm test` — Vitest unit tests (`vitest run`); `npx vitest` for watch mode
- `npm run build:lib` — builds the design-system library to `dist-lib/` (JS, CSS, and `.d.ts` via `scripts/build-lib-types.mjs`). Required before every `/design-sync` run.
- Mock login without a backend: set `VITE_MOCK_AUTH=true` in `.env.local` or the shell env (dev only; password `dev12345`, accounts `admin.dev` / `chuquan.dev` / `bld.dev` / `hr.dev` / `ketoan.dev`; `nhanvien.dev` gets `403 NO_ACCESS`; see `src/lib/mock-auth.ts`). It only fakes `/auth/login` and `/auth/me`; other `/api` calls still go to the real backend (a mock token there → 401 → back to login). The mock is installed by a dynamic import in `lib/axios.ts`, so a **full page reload** can send the first `/auth/me` to the real backend before the mock is ready (→ 401 → login) — navigate inside the SPA when testing.

## Architecture

- **i18n (react-i18next).** Default language is **Vietnamese (`vi`)**; English (`en`) is kept and is the fallback and the type source. All user-visible text (menu, titles, buttons, filter labels, table headers, errors, toasts, empty states, form validation, login) lives in `src/i18n/locales/<lng>/*.json` (namespaces `common`, `nav`, `auth`, `errors`, `roles`, `proposal`, `promotion`; `dashboard`/`team` belong to removed pages and exist in `en` only), initialised in `src/i18n/index.ts` and imported in `main.tsx`. Keys are type-checked against `en` (`src/i18n/i18next.d.ts`), and the `vi` object in `i18n/index.ts` is typed so a missing `vi` key fails the build — add every new key to both. In components use `useTranslation(ns)`; outside React (toasts, API errors, route meta) use `i18n.t('ns:key')`; zod schemas are factories taking `t` (`createLoginSchema`). Plurals use `_one`/`_other` keys with `{{count}}`. **Chinese captions are allowed only where the business design has them** (column sub-labels of the KPI proposal table such as `單位`, `審核結果`, and the 40 column headers + 6 group labels of the promotion table plus its two salary subgroups `subgroups.current`/`after` (Hiện tại 目前 / Sau khi tăng 調整後), kept in the locale files as `sub` keys), the captions of the Permissions page (layout 8: column `sub` keys, `titleZh`, `listZh`, `roleZh`, `unsavedZh`, `selectedZh`, `empty.*.zh`, the drawer title and unit-search placeholder in `roles.json`), plus the English hint under each Vietnamese evaluation result / proposal type / board decision (`results.*.hint`, `promotion:types.*.hint`, `promotion:decision.*.hint`); don't add other bilingual labels. System data (unit names, employee names, positions like `NV 職員`) is shown as received. **Users can switch between Vietnamese, Traditional Chinese (`zh`, zh-TW, same script as the LYV Excel) and English (`en`)**: `LanguageSwitch` (`components/language-switch.tsx`, VI / 中文 / EN, order = `LANGUAGES`) sits in the header and on the login page; the choice is saved in localStorage `kpi-language` (read at i18n init, `lib/language.ts` sets `<html lang>`). The `zh` object in `i18n/index.ts` is typed like `vi`, so add every new key to `vi`, `zh` and `en`. In `zh` files the bilingual pairs are swapped: Chinese in `label`, the Vietnamese original in `sub`. To add a language: copy `locales/en` to `locales/<code>`, register it in `i18n/index.ts` (+ `LANGUAGES`) and add its Intl locale in `lib/format.ts`. Fonts: Be Vietnam Pro, falling back to system CJK fonts (`--font-sans` in `index.css`); no CJK font is bundled.
- **Date/number formatting** always goes through `src/lib/format.ts` (`formatDate`, `formatNumber`, `formatPercent`, `formatMonthShort`, …); store dates as ISO `YYYY-MM-DD`. Never build date/number strings by hand. Business tables use the company convention regardless of language: `formatMoney` / `formatAccounting` → `3,000,000`, negatives `(500,000)` (colour them `text-danger-text`); `formatSlashDate` → `2017/06/02`; `formatMonthRange` → `07–09/2026`.
- **`components/ui/` stays i18n-agnostic** (it ships in the design-system library): any text is a prop with a neutral English default (`Badge` children, `Toaster` `label`/`closeLabel`, `StatCard` `trend.labels`, `PageBanner` `loadingLabel`); pages pass translated strings.

- **Login page (public, pre-auth).** `pages/auth/Login.tsx` is the "Today hub" layout: clock, quarter countdown (`lib/quarter.ts`, Asia/Ho_Chi_Minh), HR announcement and What's new from `src/config/announcements.ts` (temporary static source, later admin-managed). It must show only public info — never names or internal employee/KPI data. Cards live in `components/ui/` (`InfoCard`, `ClockCard`, `CountdownCard`, `QuarterProgress`, `AnnouncementCard`, `UpdatesList`) and are exported from the library; motion keyframes are in `index.css` and are turned off by the global `prefers-reduced-motion` rule.

- **Path alias** `@/` → `src/`.
- **Routing is metadata-driven.** `src/routes/config.ts` (`ROUTE_META`) is the single source for page title, allowed roles (`AD` Admin / `CQ` Chủ quản / `BLD` Ban lãnh đạo / `HR` Nhân sự / `KT` Kế toán; `NV` exists only as the unknown-role fallback) and sidebar entry. `title` is a key in the `nav` namespace, not display text. A new page needs a `ROUTE_META` line plus a `nav` key (en + vi) plus a route under `RequireRole` in `src/routes/index.tsx`. `/`, login and Forbidden go to `homeOf(role)`: `HOME_PATH` (`/proposals`) if the role may open it, otherwise the role's first allowed page (HR, KT → `/promotions`). **The system is not for employees**: there are no employee pages (Overview, My KPI, Evaluations, Notifications, Profile, My team were removed from routes; their files are still in the repo awaiting a delete decision).

- **Auth/session**: token + server user live in the Zustand store `src/stores/auth.ts` (`useAuthStore`), persisted to localStorage when "remember", else sessionStorage, and synced across tabs via the `storage` event. `src/lib/axios.ts` reads it through `getToken`/`setToken`/`clearToken`, owns the interceptors (Bearer header; 401 → one shared `POST /auth/refresh` (httpOnly cookie) then retry; refresh fails → clear + redirect to `/login`; normalised `ApiError`) and the `http` helpers. `src/lib/session.ts` derives the current user and role from the server user object, falling back to JWT claims, then to lowest role (NV, `roleKnown=false`) — in components use `useCurrentUser()` (reactive), outside React `getCurrentUser()`. `useMe()` (`src/hooks/use-me.ts`, called once in `MainLayout`) re-validates the session with `GET /auth/me`. Client-side role checks are navigation/display only; the server must enforce permissions.

- **Design system** lives in `src/components/ui/` and `src/index.css` (tokens in `:root`, `.dark`, `@theme inline`). Don't use `color-mix()` in `:root`/`.dark` token values: Lightning CSS emits extra `:root` fallback blocks and the token extraction in `build:lib` fails; write the mixed hex instead (see the `--grid-*` tokens). `DataGrid` (`components/ui/data-grid.tsx`) is the wide-table component: a CSS grid as wide as its container with `min-width` = sum of the columns' minimum widths (a `minmax(Npx,1fr)` column only grows into spare space), with optional `striped` rows, `rowAccent` (left stripe) and per-column `filter` buttons that show on header hover/focus or while active, with the column-group row and header sticky on top, `pinned` leading columns sticky left (opaque, `shadow-grid-pin` on their right edge once scrolled; a group spanning the pinned edge is split so its label stays in the pinned part and never covers scrolling groups, whose labels stick just after the pinned edge) and the footer (total) row sticky at the bottom of the same scroll area, so totals stay aligned when scrolling sideways. `density="comfortable"` (48px header, 56px rows, 13px text, 16px side padding; for few-column tables that fill the width with `minmax(0,Nfr)` columns, e.g. Permissions) and `hoverRows` (whole-row hover, `bg-grid-row-hover`) and `fillEmpty` (an empty table's `empty` cell fills the rest of the scroll area, centred) are opt-in, the default stays compact; `wrapHeaders` wraps long column headers (the group row is always one line, 28px, label truncated), column `note` adds a small grey line, group `collapse` folds a group into a 40px column (its pinned columns stay; −/+ button at the group's right end; `collapse.stub` is the vertical label of the narrow column, absolutely positioned so it never sets the header height), group `hidden` (`span: 0`, `{ label, stub }`) renders a group hidden by permission as a 40px locked column with a vertical label and empty cells, group `subgroups` (`{ key, label, from: <first column key>, span }`) add a second 20px header tier over those columns only — the other headers then span both rows. Without `groups` the header stays one auto-placed row (KPI proposal, Permissions). Without a footer, rows are packed to the top (`content-start`). **Full-window table pages** (KPI proposal, Promotion): `PageShell` + `TableCard fit` + `PageBanner compact` — no outer page scroll from lg; the card is as tall as its rows (no empty space, horizontal scrollbar right under the last row), at most the rest of the window, and never shorter than header + `minRows` (5) rows (measured from the DataGrid via `data-slot="data-grid-row"`/`"data-grid-footer"`); it shrinks first (`shrink-[1000]`), then other shrinkable blocks with a `min-h-*` (the promotion notes strip) give way; everything else above it is `flex-none`. It must be the direct child of the scroll container, and that container needs `flex flex-col` (`<TableCardBody className="flex flex-col">`): a `1fr` spacer row before the footer keeps the footer at the bottom of the card when there are few rows. The footer gets `shadow-grid-footer` while rows are hidden under it. Sticky cells need opaque backgrounds (`bg-card`, `bg-grid-*`). Use semantic token classes (`bg-brand-gradient`, `text-success-text`, …), never raw hex; there is a user-facing **light/dark toggle** (`lib/theme.ts`, `ThemeToggle` in the Header and on the login page, class `dark` on `<html>`, localStorage `kpi-theme`, OS preference by default, anti-flash script in `index.html`; dark tokens in `.dark` are navy blue), and the UI is fixed to the **flat** style (`lib/ui-theme.ts`, `<html data-ui="flat">`; the glass/flat toggle was removed and `useGlassUi()` is always false — the `glass` branches and `.liquid-*`/`.shell-*`/login glass CSS are leftover code): `flat` (light "soft blue" UI, no glass: the base `:root` tokens — pale blue page, sky→blue brand gradient, blue-tinted shadows — plus `.flat-backdrop` page glow and 22px white table/info cards at the end of `index.css`); the login page is flat too (no aurora, no glass crack/shatter, no seasonal decor). In glass mode the `dark` class is applied locally to get dark tokens — the content panel (`AppShell`), floating popups (`useGlassPopup`, returns nothing in flat mode) and the login screen — and token classes flip automatically inside it, so don't add `dark:` variants. Full rules and token tables: `docs/design-system.md`. `GlassCard`/mesh backgrounds are login-screen only; inner pages use flat `Card`.
- **Library entry** `src/design-system.ts` re-exports only shared UI (no router/auth/API). `src/design-system.css` imports `index.css` and lists every token/layout utility in `@source inline(...)` because Tailwind only emits classes found in source. **When adding a token or a utility that library consumers (Claude Design) should use, add it to that list**, or it ships unstyled. A new shared component must also be exported from `design-system.ts`.
- `vite.lib.config.ts` externalises `use-sync-external-store` (pulled in by Base UI Popover); bundling it inline breaks previews with a "Dynamic require" error.

## Claude Design sync (`/design-sync`)

Read `.design-sync/NOTES.md` before syncing; it records gotchas and re-sync risks. `.ds-sync/`, `ds-bundle/`, `dist-lib/` and `.design-sync/.cache/` are gitignored build output.
