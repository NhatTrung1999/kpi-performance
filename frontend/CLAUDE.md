# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Repo layout: `frontend/` (this app — React 19 + TypeScript + Vite 8 + Tailwind v4) and `docs/design-system.md` (token tables and design rules, in Vietnamese). There is no backend in the repo; the app talks to an API at `VITE_API_URL` (default `/api`). Code comments are Vietnamese. **UI text goes through i18n** (Vietnamese by default, English kept; see below) — never hard-code user-visible text in components. Unit tests use Vitest (`*.test.ts` next to the code).

## Commands (run from `frontend/`)

- `npm run dev` — Vite dev server
- `npm run build` — `tsc -b && vite build` (type-check is part of the build)
- `npm run lint` — ESLint
- `npm test` — Vitest unit tests (`vitest run`); `npx vitest` for watch mode
- `npm run build:lib` — builds the design-system library to `dist-lib/` (JS, CSS, and `.d.ts` via `scripts/build-lib-types.mjs`). Required before every `/design-sync` run.
- Mock login without a backend: set `VITE_MOCK_AUTH=true` in `.env.local` or the shell env (dev only; password `dev12345`, accounts `admin.dev` / `chuquan.dev` / `bld.dev`; `nhanvien.dev` gets `403 NO_ACCESS`; see `src/lib/mock-auth.ts`). It only fakes `/auth/login` and `/auth/me`; other `/api` calls still go to the real backend (a mock token there → 401 → back to login).

## Architecture

- **i18n (react-i18next).** Default language is **Vietnamese (`vi`)**; English (`en`) is kept and is the fallback and the type source. All user-visible text (menu, titles, buttons, filter labels, table headers, errors, toasts, empty states, form validation, login) lives in `src/i18n/locales/<lng>/*.json` (namespaces `common`, `nav`, `auth`, `errors`, `roles`, `proposal`; `dashboard`/`team` belong to removed pages and exist in `en` only), initialised in `src/i18n/index.ts` and imported in `main.tsx`. Keys are type-checked against `en` (`src/i18n/i18next.d.ts`), and the `vi` object in `i18n/index.ts` is typed so a missing `vi` key fails the build — add every new key to both. In components use `useTranslation(ns)`; outside React (toasts, API errors, route meta) use `i18n.t('ns:key')`; zod schemas are factories taking `t` (`createLoginSchema`). Plurals use `_one`/`_other` keys with `{{count}}`. **Chinese captions are allowed only where the business design has them** (column sub-labels of the KPI proposal table such as `單位`, `審核結果`, kept in the locale files as `sub` keys), plus the English hint under each Vietnamese evaluation result (`results.*.hint`); don't add other bilingual labels. System data (unit names, employee names, positions like `NV 職員`) is shown as received. To add a language: copy `locales/en` to `locales/<code>`, register it in `i18n/index.ts` and add its Intl locale in `lib/format.ts`. Fonts: Be Vietnam Pro, falling back to system CJK fonts (`--font-sans` in `index.css`); no CJK font is bundled.
- **Date/number formatting** always goes through `src/lib/format.ts` (`formatDate`, `formatNumber`, `formatPercent`, `formatMonthShort`, …); store dates as ISO `YYYY-MM-DD`. Never build date/number strings by hand. Business tables use the company convention regardless of language: `formatMoney` / `formatAccounting` → `3,000,000`, negatives `(500,000)` (colour them `text-danger-text`); `formatSlashDate` → `2017/06/02`; `formatMonthRange` → `07–09/2026`.
- **`components/ui/` stays i18n-agnostic** (it ships in the design-system library): any text is a prop with a neutral English default (`Badge` children, `Toaster` `label`/`closeLabel`, `StatCard` `trend.labels`, `PageBanner` `loadingLabel`); pages pass translated strings.

- **Login page (public, pre-auth).** `pages/auth/Login.tsx` is the "Today hub" layout: clock, quarter countdown (`lib/quarter.ts`, Asia/Ho_Chi_Minh), HR announcement and What's new from `src/config/announcements.ts` (temporary static source, later admin-managed). It must show only public info — never names or internal employee/KPI data. Cards live in `components/ui/` (`InfoCard`, `ClockCard`, `CountdownCard`, `QuarterProgress`, `AnnouncementCard`, `UpdatesList`) and are exported from the library; motion keyframes are in `index.css` and are turned off by the global `prefers-reduced-motion` rule.

- **Path alias** `@/` → `src/`.
- **Routing is metadata-driven.** `src/routes/config.ts` (`ROUTE_META`) is the single source for page title, allowed roles (`AD` Admin / `CQ` Chủ quản / `BLD` Ban lãnh đạo; `NV` exists only as the unknown-role fallback) and sidebar entry. `title` is a key in the `nav` namespace, not display text. A new page needs a `ROUTE_META` line plus a `nav` key (en + vi) plus a route under `RequireRole` in `src/routes/index.tsx`. `HOME_PATH` (`/proposals`) is where `/`, login and Forbidden go. **The system is not for employees**: there are no employee pages (Overview, My KPI, Evaluations, Notifications, Profile, My team were removed from routes; their files are still in the repo awaiting a delete decision).
- **Pages by role.** Only roles in `SIDEBAR_ROLES` (`AD`) get the sidebar (`MainLayout` passes no sidebar to `AppShell` otherwise, and `Header` then shows the logo instead of the page title). Admin: Kỳ đánh giá `/periods` and Lịch sử `/history` (both `UnderConstruction` for now), Đề xuất KPI `/proposals`, Phân quyền `/roles`. Chủ quản: only `/proposals`, editable. BLĐ: only `/proposals`, read-only for now.
- **Auth/session**: token + server user live in the Zustand store `src/stores/auth.ts` (`useAuthStore`), persisted to localStorage when "remember", else sessionStorage, and synced across tabs via the `storage` event. `src/lib/axios.ts` reads it through `getToken`/`setToken`/`clearToken`, owns the interceptors (Bearer header; 401 → one shared `POST /auth/refresh` (httpOnly cookie) then retry; refresh fails → clear + redirect to `/login`; normalised `ApiError`) and the `http` helpers. `src/lib/session.ts` derives the current user and role from the server user object, falling back to JWT claims, then to lowest role (NV, `roleKnown=false`) — in components use `useCurrentUser()` (reactive), outside React `getCurrentUser()`. `useMe()` (`src/hooks/use-me.ts`, called once in `MainLayout`) re-validates the session with `GET /auth/me`. Client-side role checks are navigation/display only; the server must enforce permissions.
- **Access model.** Only these users can sign in: the single **admin** (`AD`, the account in backend `.env` `ADMIN_ACCOUNT`), **managers** (`CQ`) granted by the admin on the Permissions page, and the **board** (`BLD`; role codes `BLD`/`BOARD`/`DIRECTOR` are accepted; backend support pending); everyone else gets `403 NO_ACCESS` at login (`LoginFailure` kind `no-access`). A manager only sees employees in the teams assigned to them — the backend filters `/api/departments*`; the UI never filters for security. `ROLE_GATING` in `routes/config.ts` is on; `/roles` is `AD` only. The Permissions page (`pages/roles/`) keys people by `Person_Serial_Key` (`Person.psk`), edits are a local draft until "Save changes" (`PUT /api/permissions/managers`, `use-permissions.ts`); tree leaf ids ↔ scope units via `leafToScope`/`scopeToLeaf`. (`pages/team/`, the old My team page, is no longer routed.)
- **KPI proposal (`/proposals`, `pages/proposals/`).** Data comes from `services/kpiProposal.ts`, which is **sample data for now** (10 employees as in the design + 1 resigned who is filtered out; manager scope filtered in the service with a TODO that the server must enforce it; draft/status kept in localStorage). Its functions keep the signatures the real API will have (`get`, `saveDraft`, `submit` for CQ, `approve`/`return` for BLĐ); the page calls them through TanStack Query (`use-kpi-proposal.ts`). The service keeps every HR field separate (card no., status, leave, resign date…) because the Excel export needs all original columns; the table only merges them for display (Họ tên + số thẻ, Tình trạng = Pill + date line). Status flow: `draft` → `submitted` → `approved` (BLĐ "Trả lại" goes back to `draft`). **Per-column edit rights live in `config/kpi-proposal.ts` (`ROLE_EDIT`, `canEdit`, `isEditor`)**: CQ edits duties/result/this-period/note while `draft`; BLĐ edits only "Quyết định BLĐ" while `submitted`; Admin is read-only — components only call `can(field)`, never check roles themselves, and the mock service drops fields a role may not write (TODO: the server must reject them with 403). ABC ratings arrive as text ("1B, 2C") and are always read through `parseAbcRatings`/`countGrade` (`lib/abc.ts`), never by string matching; rules are `ABC_RULES` (≥3C must pick a reducing result, 2C may increase at most 500,000 — exactly 500,000 is allowed); a violation shows a warning icon with a tooltip next to "Kỳ này" and disables submit. Pure helpers in `pages/proposals/logic.ts` (`validateRow`, `summarize`, `diffOf`, `percentOf`, colour helpers) are unit-tested in `logic.test.ts` against the sample data (11,000,000 → 8,000,000, diff (3,000,000)). Colours: only Họ tên, Kết quả, Kỳ này and Chênh lệch take the result colour (reduce/cancel `text-danger-text`, increase/new `text-info`), plus a 3px left stripe (`rowAccent`, neutral = `bg-muted-foreground`); suspended-KPI or resigning rows get `bg-grid-row-muted`. ABC chips (`AbcChip`) are coloured by grade, never by row colour. The total row sums every visible row. All 14 columns fit at 1440px without a sidebar (CQ/BLĐ); Admin (sidebar) scrolls horizontally with Bộ phận/Họ tên pinned.
- **State management.** Server data → **TanStack Query v5** (`QueryClientProvider` + dev-only `ReactQueryDevtools` in `main.tsx`, client in `src/lib/query-client.ts`: `staleTime` 30s, no retry on 4xx). `queryFn`/`mutationFn` call the `http` helpers from `lib/axios.ts` (keeps the refresh-token interceptor) — never `useEffect` + `useState` fetching, never raw axios in components. Shared UI state → **Zustand** stores in `src/stores/` (`create<T>()(...)`, read with selectors, e.g. `usePeriodStore((s) => s.period)`; put such values in the `queryKey`). Forms stay on react-hook-form + zod; local UI on `useState`. `logout()` calls `queryClient.clear()`.
- **Design system** lives in `src/components/ui/` and `src/index.css` (tokens in `:root`, `.dark`, `@theme inline`). Don't use `color-mix()` in `:root`/`.dark` token values: Lightning CSS emits extra `:root` fallback blocks and the token extraction in `build:lib` fails; write the mixed hex instead (see the `--grid-*` tokens). `DataGrid` (`components/ui/data-grid.tsx`) is the wide-table component: a CSS grid as wide as its container with `min-width` = sum of the columns' minimum widths (a `minmax(Npx,1fr)` column only grows into spare space), with optional `striped` rows, `rowAccent` (left stripe) and per-column `filter` buttons that show on header hover/focus or while active, with the column-group row and header sticky on top, `pinned` leading columns sticky left and the footer (total) row sticky at the bottom of the same scroll area, so totals stay aligned when scrolling sideways. It must be the direct child of the scroll container, and that container needs `flex flex-col` (`<TableCardBody className="flex flex-col">`): a `1fr` spacer row before the footer keeps the footer at the bottom of the card when there are few rows. The footer gets `shadow-grid-footer` while rows are hidden under it. Sticky cells need opaque backgrounds (`bg-card`, `bg-grid-*`). Use semantic token classes (`bg-brand-gradient`, `text-success-text`, …), never raw hex; dark mode is the `dark` class on `<html>` and token classes flip automatically, so don't add `dark:` variants. Full rules and token tables: `docs/design-system.md`. `GlassCard`/mesh backgrounds are login-screen only; inner pages use flat `Card`.
- **Library entry** `src/design-system.ts` re-exports only shared UI (no router/auth/API). `src/design-system.css` imports `index.css` and lists every token/layout utility in `@source inline(...)` because Tailwind only emits classes found in source. **When adding a token or a utility that library consumers (Claude Design) should use, add it to that list**, or it ships unstyled. A new shared component must also be exported from `design-system.ts`.
- `vite.lib.config.ts` externalises `use-sync-external-store` (pulled in by Base UI Popover); bundling it inline breaks previews with a "Dynamic require" error.

## Claude Design sync (`/design-sync`)

Config and notes live in `.design-sync/` (`config.json`, `NOTES.md`, `conventions.md`, authored `previews/*.tsx` — all committed). Read `.design-sync/NOTES.md` before syncing; it records gotchas and re-sync risks. `.ds-sync/`, `ds-bundle/`, `dist-lib/` and `.design-sync/.cache/` are gitignored build output. If you rename a token/class or a component, re-validate `.design-sync/conventions.md` against `ds-bundle/_ds_bundle.css`.
