# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Repo layout: `frontend/` (this app — React 19 + TypeScript + Vite 8 + Tailwind v4) and `docs/design-system.md` (token tables and design rules, in Vietnamese). There is no backend in the repo; the app talks to an API at `VITE_API_URL` (default `/api`). Code comments are Vietnamese. **UI text goes through i18n** (Vietnamese by default, English kept; see below) — never hard-code user-visible text in components. Unit tests use Vitest (`*.test.ts` next to the code).

## Commands (run from `frontend/`)

- `npm run dev` — Vite dev server
- `npm run build` — `tsc -b && vite build` (type-check is part of the build)
- `npm run lint` — ESLint
- `npm test` — Vitest unit tests (`vitest run`); `npx vitest` for watch mode
- `npm run build:lib` — builds the design-system library to `dist-lib/` (JS, CSS, and `.d.ts` via `scripts/build-lib-types.mjs`). Required before every `/design-sync` run.
- Mock login without a backend: set `VITE_MOCK_AUTH=true` in `.env.local` or the shell env (dev only; password `dev12345`, accounts `admin.dev` / `chuquan.dev` / `bld.dev` / `hr.dev` / `ketoan.dev`; `nhanvien.dev` gets `403 NO_ACCESS`; see `src/lib/mock-auth.ts`). It only fakes `/auth/login` and `/auth/me`; other `/api` calls still go to the real backend (a mock token there → 401 → back to login). The mock is installed by a dynamic import in `lib/axios.ts`, so a **full page reload** can send the first `/auth/me` to the real backend before the mock is ready (→ 401 → login) — navigate inside the SPA when testing.

## Architecture

- **i18n (react-i18next).** Default language is **Vietnamese (`vi`)**; English (`en`) is kept and is the fallback and the type source. All user-visible text (menu, titles, buttons, filter labels, table headers, errors, toasts, empty states, form validation, login) lives in `src/i18n/locales/<lng>/*.json` (namespaces `common`, `nav`, `auth`, `errors`, `roles`, `proposal`, `promotion`; `dashboard`/`team` belong to removed pages and exist in `en` only), initialised in `src/i18n/index.ts` and imported in `main.tsx`. Keys are type-checked against `en` (`src/i18n/i18next.d.ts`), and the `vi` object in `i18n/index.ts` is typed so a missing `vi` key fails the build — add every new key to both. In components use `useTranslation(ns)`; outside React (toasts, API errors, route meta) use `i18n.t('ns:key')`; zod schemas are factories taking `t` (`createLoginSchema`). Plurals use `_one`/`_other` keys with `{{count}}`. **Chinese captions are allowed only where the business design has them** (column sub-labels of the KPI proposal table such as `單位`, `審核結果`, and the 40 column headers + 6 group labels of the promotion table, kept in the locale files as `sub` keys), plus the English hint under each Vietnamese evaluation result / proposal type / board decision (`results.*.hint`, `promotion:types.*.hint`, `promotion:decision.*.hint`); don't add other bilingual labels. System data (unit names, employee names, positions like `NV 職員`) is shown as received. To add a language: copy `locales/en` to `locales/<code>`, register it in `i18n/index.ts` and add its Intl locale in `lib/format.ts`. Fonts: Be Vietnam Pro, falling back to system CJK fonts (`--font-sans` in `index.css`); no CJK font is bundled.
- **Date/number formatting** always goes through `src/lib/format.ts` (`formatDate`, `formatNumber`, `formatPercent`, `formatMonthShort`, …); store dates as ISO `YYYY-MM-DD`. Never build date/number strings by hand. Business tables use the company convention regardless of language: `formatMoney` / `formatAccounting` → `3,000,000`, negatives `(500,000)` (colour them `text-danger-text`); `formatSlashDate` → `2017/06/02`; `formatMonthRange` → `07–09/2026`.
- **`components/ui/` stays i18n-agnostic** (it ships in the design-system library): any text is a prop with a neutral English default (`Badge` children, `Toaster` `label`/`closeLabel`, `StatCard` `trend.labels`, `PageBanner` `loadingLabel`); pages pass translated strings.

- **Login page (public, pre-auth).** `pages/auth/Login.tsx` is the "Today hub" layout: clock, quarter countdown (`lib/quarter.ts`, Asia/Ho_Chi_Minh), HR announcement and What's new from `src/config/announcements.ts` (temporary static source, later admin-managed). It must show only public info — never names or internal employee/KPI data. Cards live in `components/ui/` (`InfoCard`, `ClockCard`, `CountdownCard`, `QuarterProgress`, `AnnouncementCard`, `UpdatesList`) and are exported from the library; motion keyframes are in `index.css` and are turned off by the global `prefers-reduced-motion` rule.

- **Path alias** `@/` → `src/`.
- **Routing is metadata-driven.** `src/routes/config.ts` (`ROUTE_META`) is the single source for page title, allowed roles (`AD` Admin / `CQ` Chủ quản / `BLD` Ban lãnh đạo / `HR` Nhân sự / `KT` Kế toán; `NV` exists only as the unknown-role fallback) and sidebar entry. `title` is a key in the `nav` namespace, not display text. A new page needs a `ROUTE_META` line plus a `nav` key (en + vi) plus a route under `RequireRole` in `src/routes/index.tsx`. `/`, login and Forbidden go to `homeOf(role)`: `HOME_PATH` (`/proposals`) if the role may open it, otherwise the role's first allowed page (HR, KT → `/promotions`). **The system is not for employees**: there are no employee pages (Overview, My KPI, Evaluations, Notifications, Profile, My team were removed from routes; their files are still in the repo awaiting a delete decision).
- **Pages by role.** Only roles in `SIDEBAR_ROLES` (`AD`, `CQ`, `BLD` — the roles with more than one page) get the sidebar (`MainLayout` passes no sidebar to `AppShell` otherwise, and `Header` then shows the logo instead of the page title). Admin: Kỳ đánh giá `/periods` and Lịch sử `/history` (both `UnderConstruction` for now), Đề xuất KPI `/proposals`, Thăng chức & lương `/promotions`, Phân quyền `/roles`. Chủ quản: `/proposals` and `/promotions`. BLĐ: `/proposals` and `/promotions`. HR and Kế toán: only `/promotions`.
- **Auth/session**: token + server user live in the Zustand store `src/stores/auth.ts` (`useAuthStore`), persisted to localStorage when "remember", else sessionStorage, and synced across tabs via the `storage` event. `src/lib/axios.ts` reads it through `getToken`/`setToken`/`clearToken`, owns the interceptors (Bearer header; 401 → one shared `POST /auth/refresh` (httpOnly cookie) then retry; refresh fails → clear + redirect to `/login`; normalised `ApiError`) and the `http` helpers. `src/lib/session.ts` derives the current user and role from the server user object, falling back to JWT claims, then to lowest role (NV, `roleKnown=false`) — in components use `useCurrentUser()` (reactive), outside React `getCurrentUser()`. `useMe()` (`src/hooks/use-me.ts`, called once in `MainLayout`) re-validates the session with `GET /auth/me`. Client-side role checks are navigation/display only; the server must enforce permissions.
- **Access model.** Only these users can sign in: the single **admin** (`AD`, the account in backend `.env` `ADMIN_ACCOUNT`), **managers** (`CQ`) granted by the admin on the Permissions page, the **board** (`BLD`; role codes `BLD`/`BOARD`/`DIRECTOR` are accepted; backend support pending), **HR** (`HR`/`NS`) and **Accounting** (`KT`/`ACCOUNTING`/`ACCOUNTANT`) for the promotion screen (backend support and how they are granted are pending); everyone else gets `403 NO_ACCESS` at login (`LoginFailure` kind `no-access`). A manager only sees employees in the teams assigned to them — the backend filters `/api/departments*`; the UI never filters for security. `ROLE_GATING` in `routes/config.ts` is on; `/roles` is `AD` only. The Permissions page (`pages/roles/`) keys people by `Person_Serial_Key` (`Person.psk`), edits are a local draft until "Save changes" (`PUT /api/permissions/managers`, `use-permissions.ts`); tree leaf ids ↔ scope units via `leafToScope`/`scopeToLeaf`. (`pages/team/`, the old My team page, is no longer routed.)
- **KPI proposal (`/proposals`, `pages/proposals/`).** Data comes from `services/kpiProposal.ts`, which is **sample data for now** (10 employees as in the design + 1 resigned who is filtered out; manager scope filtered in the service with a TODO that the server must enforce it; draft/status kept in localStorage). Its functions keep the signatures the real API will have (`get`, `saveDraft`, `submit` for CQ, `approve`/`return` for BLĐ); the page calls them through TanStack Query (`use-kpi-proposal.ts`). The service keeps every HR field separate (card no., status, leave, resign date…) because the Excel export needs all original columns; the table only merges them for display (Họ tên + số thẻ, Tình trạng = Pill + date line). Status flow: `draft` → `submitted` → `approved` (BLĐ "Trả lại" goes back to `draft`). **Per-column edit rights live in `config/kpi-proposal.ts` (`ROLE_EDIT`, `canEdit`, `isEditor`)**: CQ edits duties/result/this-period/note while `draft`; BLĐ edits only "Quyết định BLĐ" while `submitted`; Admin is read-only — components only call `can(field)`, never check roles themselves, and the mock service drops fields a role may not write (TODO: the server must reject them with 403). ABC ratings arrive as text ("1B, 2C") and are always read through `parseAbcRatings`/`countGrade` (`lib/abc.ts`), never by string matching; rules are `ABC_RULES` (≥3C must pick a reducing result, 2C may increase at most 500,000 — exactly 500,000 is allowed); a violation shows a warning icon with a tooltip next to "Kỳ này" and disables submit. Pure helpers in `pages/proposals/logic.ts` (`validateRow`, `summarize`, `diffOf`, `percentOf`, colour helpers) are unit-tested in `logic.test.ts` against the sample data (11,000,000 → 8,000,000, diff (3,000,000)). Colours: only Họ tên, Kết quả, Kỳ này and Chênh lệch take the result colour (reduce/cancel `text-danger-text`, increase/new `text-info`), plus a 3px left stripe (`rowAccent`, neutral = `bg-muted-foreground`); suspended-KPI or resigning rows get `bg-grid-row-muted`. ABC chips (`AbcChip`) are coloured by grade, never by row colour. The total row sums every visible row. All 14 columns fit at 1440px without a sidebar; with the sidebar (AD, CQ, BLĐ since `/promotions` exists) the table scrolls horizontally with Bộ phận/Họ tên pinned unless the sidebar is collapsed.
- **Promotion & salary (`/promotions`, `pages/promotions/`).** Layout 7 (7a CQ, 7b BLĐ, 7c BLĐ dark; built on 5c) of the Claude Design project; spec `docs/specs/Website_for_Promotion___Salary_proposal.xlsx` (sheet 2026年07月名單 = the 40 columns A–AN in 6 groups, Promotion levels, SUM, hidden General process / Evaluation Process). Data comes from `services/promotionProposal.ts`, **sample data for now** (5 review groups named as in sheet SUM, each with its own status; TRANSFER TEAM holds the 3 Excel rows; manager scope by email with a TODO; drafts/status in localStorage; uploaded org-chart files only in memory). Signatures match the future API (`get` per group, `saveDraft`, `submit` CQ, `approve`/`return` BLĐ with a required reason, `uploadOrgChart`/`removeOrgChart`), called through TanStack Query (`use-promotion-proposal.ts`). Status per group: `draft` → `submitted` → `approved`, BLĐ "Trả lại CQ" → `returned` (CQ edits again; **TODO chị Kitty**: confirm the return feature).
  - **All rights and rules live in ONE file, `config/promotion-proposal.ts`.** `GROUP_VIEW` = which column groups (`hr`, `cq`, `kpi`, `salary`, `hrOpinion`, `board`) each role sees: CQ only `hr`/`cq`/`kpi`; HR, KT, BLĐ all six; Admin all except `salary` (**TODO chị Kitty**: confirm, file says only BLĐ/Accounting/HR see salary). Groups a role can't see are not rendered at all, and the service strips them from the returned rows (`visibleRow` — TODO: the server must do this; salary must never reach CQ/Admin). `ROLE_EDIT` per column: CQ the CQ group (N–R) while `draft`/`returned`; HR only "Ý kiến của nhân sự" while `submitted`; KT only the estimated salary columns AC–AF while `submitted`; BLĐ only the board group while `submitted`; Admin read-only (TODO: the Admin validation step before HR/KT is not built). Components only call `canEdit`, and the mock service drops fields a role may not write (TODO: server 403).
  - Rules (config + unit tests in `logic.test.ts`): no permanent contract + ≥4C in 12 months → the proposal cell is locked with a tooltip; permanent contract + ≥4C → selectable but the reason is required (submit blocked until filled); new title only the next level within the same division (`POSITION_LADDER`, `nextPositions`; code → 17-level mapping `POSITION_CODES` is **TODO: to confirm**, production-division ladder **TODO: missing**); headcount budget per group recomputed on every pick — promotion 5%, raise 10% local / 5% expat (`HEADCOUNT_RULES`, `mode: 'warn'` = orange warning, never blocks — **TODO: confirm warn vs block**); BLĐ "Từ chối" → granted raise forced to 0 and new title locked, reason required in red, "Phê duyệt nhóm" disabled while a rejected row has no reason. CQ must upload both org charts (before/after, PDF/PNG/JPG ≤ 10MB, `orgChartError`) before "Gửi đề xuất"; other roles only View/Download them.
  - Formulas (`pages/promotions/logic.ts`): Tổng lương hiện tại = HĐ + bình bầu + chuyên cần + phí sinh hoạt (the Excel `=SUM(T5:AA5)` is wrong — circular and sums dates/salary history; a test guards it); Tổng sau tăng = the four new parts; Chênh lệch cũ & mới = new − current; Chênh lệch đề xuất & thực tế = granted − proposed (Lý Văn C → (1,000,000)); "Theo bậc lương Cty" has no amount yet → difference "—" (TODO: salary scale table). Seniority = (effective date − join date)/365.

  - Page texts come verbatim from the file: Notes (B16–B19, collapsible card at the top, typos kept), "Theo quy định Cty:" (A10–B13, two boxes with the "=> CQ …" result + Pill), salary-group lock tooltip (T9 + T10, VI + CN), headcount-budget tooltip on the quota meters (A21–A23).   - UI: `DataGrid` with `wrapHeaders` (all 40 headers + 6 group labels verbatim Vietnamese + Chinese from the file, in `promotion:cols.*`/`groups.*`, never truncated), 3 pinned columns, collapsible groups (`collapse`), group tones `read`/`warn`/`info`/`salary`/`success`. Multi-value cells (promotion history, salary history) show the 2 latest + a "+N" chip opening a Popover. New-title selects show code + system name on two lines (never clipped); the board's reject reason is an `AutoTextarea` (`cells.tsx`, `field-sizing: content` with a scrollHeight fallback) that grows with its text. "Trả lại CQ" keeps its confirm button enabled and shows a required-reason error when clicked empty. BLĐ, HR, KT and Admin pick the review group (with per-group status) instead of a department filter; CQ keeps the department filter (and the group picker only when it manages several groups).
- **State management.** Server data → **TanStack Query v5** (`QueryClientProvider` + dev-only `ReactQueryDevtools` in `main.tsx`, client in `src/lib/query-client.ts`: `staleTime` 30s, no retry on 4xx). `queryFn`/`mutationFn` call the `http` helpers from `lib/axios.ts` (keeps the refresh-token interceptor) — never `useEffect` + `useState` fetching, never raw axios in components. Shared UI state → **Zustand** stores in `src/stores/` (`create<T>()(...)`, read with selectors, e.g. `usePeriodStore((s) => s.period)`; put such values in the `queryKey`). Forms stay on react-hook-form + zod; local UI on `useState`. `logout()` calls `queryClient.clear()`.
- **Design system** lives in `src/components/ui/` and `src/index.css` (tokens in `:root`, `.dark`, `@theme inline`). Don't use `color-mix()` in `:root`/`.dark` token values: Lightning CSS emits extra `:root` fallback blocks and the token extraction in `build:lib` fails; write the mixed hex instead (see the `--grid-*` tokens). `DataGrid` (`components/ui/data-grid.tsx`) is the wide-table component: a CSS grid as wide as its container with `min-width` = sum of the columns' minimum widths (a `minmax(Npx,1fr)` column only grows into spare space), with optional `striped` rows, `rowAccent` (left stripe) and per-column `filter` buttons that show on header hover/focus or while active, with the column-group row and header sticky on top, `pinned` leading columns sticky left (opaque, `shadow-grid-pin` on their right edge once scrolled; a group spanning the pinned edge is split so its label stays in the pinned part and never covers scrolling groups, whose labels stick just after the pinned edge) and the footer (total) row sticky at the bottom of the same scroll area, so totals stay aligned when scrolling sideways. `wrapHeaders` wraps long headers/group labels (group-row height is measured), column `note` adds a small grey line, group `collapse` folds a group into a 40px column (its pinned columns stay). Without a footer, rows are packed to the top (`content-start`). It must be the direct child of the scroll container, and that container needs `flex flex-col` (`<TableCardBody className="flex flex-col">`): a `1fr` spacer row before the footer keeps the footer at the bottom of the card when there are few rows. The footer gets `shadow-grid-footer` while rows are hidden under it. Sticky cells need opaque backgrounds (`bg-card`, `bg-grid-*`). Use semantic token classes (`bg-brand-gradient`, `text-success-text`, …), never raw hex; dark mode is the `dark` class on `<html>` and token classes flip automatically, so don't add `dark:` variants. Full rules and token tables: `docs/design-system.md`. `GlassCard`/mesh backgrounds are login-screen only; inner pages use flat `Card`.
- **Library entry** `src/design-system.ts` re-exports only shared UI (no router/auth/API). `src/design-system.css` imports `index.css` and lists every token/layout utility in `@source inline(...)` because Tailwind only emits classes found in source. **When adding a token or a utility that library consumers (Claude Design) should use, add it to that list**, or it ships unstyled. A new shared component must also be exported from `design-system.ts`.
- `vite.lib.config.ts` externalises `use-sync-external-store` (pulled in by Base UI Popover); bundling it inline breaks previews with a "Dynamic require" error.

## Claude Design sync (`/design-sync`)

Config and notes live in `.design-sync/` (`config.json`, `NOTES.md`, `conventions.md`, authored `previews/*.tsx` — all committed). Read `.design-sync/NOTES.md` before syncing; it records gotchas and re-sync risks. `.ds-sync/`, `ds-bundle/`, `dist-lib/` and `.design-sync/.cache/` are gitignored build output. If you rename a token/class or a component, re-validate `.design-sync/conventions.md` against `ds-bundle/_ds_bundle.css`.
